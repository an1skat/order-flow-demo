# Оплачене замовлення → ТТН → чек → CRM

Демо інтеграції для інтернет-магазину: після оплати автоматично створюється ТТН Нової Пошти, пробивається фіскальний чек у Checkbox, а номер ТТН записується в замовлення KeyCRM.

Простий «щасливий шлях» тут не головне. Демо показує, що відбувається, коли щось іде не так:

| Ситуація | Що робить система |
| --- | --- |
| Платіжка надіслала вебхук двічі | Друга подія з тим самим `event_id` ігнорується, ТТН не дублюється |
| Нова Пошта не відповіла (таймаут) | До 3 спроб із паузою 0.4 → 1 → 2 с |
| Зміна в касі Checkbox закрита | Система відкриває зміну сама і пробиває чек ще раз |
| KeyCRM повернув 5xx | Повтор, решта кроків не переробляється |
| Покупець ввів некоректний телефон | Зупинка ще до виклику Нової Пошти, зрозуміла причина в журналі, менеджер виправляє телефон і запускає повтор |
| Повторний запуск обробки | Кожен крок ідемпотентний: уже створені ТТН і чек не створюються вдруге |
| Підроблений вебхук | Перевірка підпису HMAC-SHA256 (`X-Signature`), інакше 401 |

## Як влаштовано

```
app/
  main.py      HTTP: вебхук /webhooks/order-paid, демо-ендпоінти, сторінка
  pipeline.py  кроки, ідемпотентність, повтори, обробка помилок
  clients.py   клієнти Нової Пошти, Checkbox, KeyCRM + симулятори з тими самими інтерфейсами
  errors.py    TransientError / PermanentError / ShiftClosedError
  db.py        SQLite: замовлення, журнал подій, оброблені вебхуки
tests/         сценарії вище як тести
```

Ключова ідея — три типи помилок. Тимчасові повторюємо. Помилки в даних зупиняють процес і показуються людині: повтор їх не виправить. Закрита зміна — окремий відомий випадок із власним виправленням.

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
# http://localhost:8000
pytest -q
```

## Режими

За замовчуванням працюють **симулятори**: справжні ключі в публічне демо не кладу. Щоб увімкнути справжні API, задайте змінні з `.env.example`. Клієнти написані за публічною документацією Нової Пошти (API 2.0), Checkbox і KeyCRM OpenAPI. Перед використанням у продакшні їх треба перевірити на тестовому акаунті конкретного магазину. Зокрема, звірити поле трекінгу в KeyCRM.
